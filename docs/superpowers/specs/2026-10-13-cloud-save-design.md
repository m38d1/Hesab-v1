# ذخیرهٔ ابری — طرح

تاریخ: ۱۳ مهر ۱۴۰۵ · وضعیت: برای بازبینی

## هدف

داده‌های مالی بین دستگاه‌های مختلف جابه‌جا شود، بدون آنکه کاربر بخواهد هنگام
باز کردن برنامه چیزی وارد کند. برنامه مثل امروز کار کند؛ ذخیرهٔ ابری فقط یک
گزینهٔ اختیاری در تنظیمات باشد.

## تصمیم‌های قطعی

| موضوع | تصمیم |
|---|---|
| بک‌اند | Cloudflare Workers + D1 |
| احراز هویت | بدون نام کاربری و رمز؛ یک «کلید بازیابی» |
| بازیابی | همان کلید بازیابی؛ نه سؤال امنیتی، نه ایمیل |
| ورود اجباری | ندارد؛ برنامه بدون حساب هم کامل کار می‌کند |
| مدل رمزگذاری | سرور کلید رمزگشایی را نگه می‌دارد |
| محل دکمه | کارت جدید در صفحهٔ تنظیمات |
| نام رشته | «کلید بازیابی» |

## معماری

GitHub Pages سایت را سرو می‌کند. یک Worker جدا روی
`*.workers.dev` نشسته و فقط مسیرهای `/api/*` را می‌پاسخ��د.

سایت روی دامنهٔ خودش است و Worker روی دامنهٔ خودش، پس درخواست‌ها **بین‌دامنه‌ای**
می‌شوند. کلاینت باید آدرس پایه را از `/api` به دامنهٔ Worker تغییر دهد و Worker
باید هدرهای CORS بدهد. این تنها تغییر زیرساختی است.

```
  مرورگر ──https──> GitHub Pages        (app.js, app.css, …)
     │
     └──https──> Worker                 (/api/join, /pull, /push, /revoke)
                    │
                    └──> D1             (users, sessions)
```

## مدل داده

### جدول `users`

| ستون | نوع | توضیح |
|---|---|---|
| `k` | TEXT PK | خودِ کلید بازیابی، نرمال‌شده |
| `rev` | INTEGER | شمارندهٔ نسخه، از ۱ شروع می‌شود |
| `iv` | TEXT | IV از آخرین رمزنگاری |
| `ct` | TEXT | متن رمزشده |
| `ts` | INTEGER | زمان آخرین نوشتن، میلی‌ثانیه |

### جدول `sessions`

| ستون | نوع | توضیح |
|---|---|---|
| `h` | TEXT PK | هش `token` |
| `k` | TEXT | کلید کاربر |
| `ts` | INTEGER | زمان ساخت |

توکن ۳۲ بایت تصادفی است و **فقط هشش** در D1 ذخیره می‌شود.

## قرارداد API

همهٔ پاسخ‌ها JSON هستند. خطاها شکل `{ "error": "<code>" }` دارند و کلاینت
از قبل این کدها را می‌شناسد: `taken`, `invalid`, `locked`, `rate_limited`,
`too_large`, `unauthorized`, `server`.

| مسیر | بدنه | کدهای خطا |
|---|---|---|
| `POST /join` | `{k}` | `taken`, `invalid`, `rate_limited` |
| `POST /pull` | توکن در هدر | `unauthorized`, `rate_limited` |
| `POST /push` | `{rev, iv, ct}` + توکن | `unauthorized`, `too_large` |
| `POST /revoke` | توکن در هدر | `unauthorized` |

پاسخ‌ها:

- `join` → `{token, rev}`؛ `rev` برابر ۱ و `iv`/`ct` تهی، چون هنوز چیزی نوشته نشده
- `pull` → `{token, rev, iv, ct}`؛ اگر `ct` تهی باشد، کلاینت `empty` می‌گیرد
- `push` → `{rev}`؛ **تعارض با کد وضعیت `409` و بدنهٔ تهی** گزارش می‌شود، نه با
  `error`، چون کلاینت `r.status === 409` را می‌سنجد
- `revoke` → `{ok: true}`

## کلید بازیابی

۶ گروه ۵ نویسه‌ای از الفبای Crockford Base32، با خط تیره جدا شده:

```
7KQ4M-2XPT9-BWHF3-R8JDL-N5VCQ
```

۱۵۰ بیت آنتروپی. الفبا نویسه‌های `I`, `L`, `O`, `U` را ندارد و هنگام خواندن
هم به `0` و `1` نگاشت می‌شوند تا اشتباه تایپی مهم نباشد.

کلید از `crypto.getRandomValues` می‌آید، به شکل `enc` در `localStorage` و در
`S.k` می‌نشیند، و همان کلید ورود به Worker و AES-GCM است.

## تغییرات کلاینت

کد همگام‌سازی موجود در `app.js` (خطوط ۳۱۱۹ تا ۳۵۶۰) برای مدل نام کاربری/رمز
نوشته شده. این‌ها عوض می‌شوند:

1. **آدرس پایه.** `syApi` به‌جای `'/api' + path` از `SYNC_URL + path` استفاده
   می‌کند. `SYNC_URL` یک ثابت در بالای `app.js` است، نه متای HTML — چون Worker
   روی دامنهٔ خودش است و مقدارش باید در باندل باشد.
2. **حذف `syKeys`.** دیگر PBKDF2 لازم نیست؛ کلید از قبل تصادفی است.
3. **حذف مسیرهای بی‌استفاده:** `/login`, `/register`, `/logout`, `/password`.
4. **مسیر `/join`** جای آن‌ها را می‌گیرد و کلید را می‌فرستد.
5. **`SY`** به `{k, token, rev, dirty, ver, last}` کوچک می‌شود. شرط اعتبارسنجی
   `syLoad` از `SY.u && SY.token && SY.key` به `SY.k && SY.token` تغییر می‌کند.
6. **صفحهٔ کلید بازیابی** جای فرم ورود: یک بار کلید ساخته و با دکمهٔ «کپی»
   نشان داده می‌شود، به‌همراه هشدار که این متن همه‌چیز است.
7. **کارت تنظیمات.** یک کارت «ذخیرهٔ ابری» با سوییچ روشن/خاموش، وضعیت
   «✓ همگام · آخرین: …»، و دکمهٔ «خاموش کردن» که کلید و نشست را پاک می‌کند.
8. **متن رابط.** جملهٔ «سرور نمی‌تواند داده‌هایت را بخواند» حذف می‌شود، چون در
   این مدل سرور کلید را دارد. جایش: «کلید بازیابی را جایی امن نگه دار. هر کس آن را
   داشته باشد، داده‌هایت را می‌بیند.»

`SYNC_OFF` دست‌نخورده می‌ماند و همچنان کلید خاموش کامل است: تا وقتی Worker
واقعاً منتشر نشده، همان `<meta name="hesab-sync" content="off">` در `index.html`
می‌ماند و کارت اصلاً رندر نمی‌شود. بعد از استقرار، مقدار به `on` تغییر می‌کند.

پس از `join`، هر تغییر `syDirty()` را صدا می‌زند که با تأخیر ۱۰ ثانیه‌ای
`syPush` می‌کند — همان رفتار موجود.

## محدودیت نرخ

روی `/join` و `/pull`: حداکثر ۳۰ درخواست در دقیقه برای هر کلید. روی `/push`:
۶۰ درخواست در دقیقه. رد شدن با `429` و `error: "rate_limited"`.

محدودیت در حافظهٔ Worker نگه داشته می‌شود (یک `Map` با پاک‌سازی دوره‌ای)،
نه در D1، چون برای یک کاربر لازم نیست پایدار باشد.

## آنچه انجام نمی‌دهیم

- چند کاربر واقعی: هر کلید یک دفترچهٔ مستقل است.
- تاریخچهٔ نسخه‌ها: فقط آخرین نسخه نگه داشته می‌شود.
- بازیابی رمز: چون کلید خودش نقش رمز را دارد، چیزی برای بازیابی نمانده.
- نشست چنددستگاهی: هر دستگاه نشست خودش را دارد؛ `pull` با `rev` هماهنگ می‌کند.

## تست

۱. **ادغام.** دو دستگاه با یک کلید: روی هر دو `rev` یکسان شروع می‌شود؛ دستگاه
   اول می‌نویسد، دستگاه دوم `pull` می‌زند و `409` می‌گیرد، ادغام اجرا می‌شود،
   مجموع تراکنش‌های هر دو طرف حفظ می‌شود.
۲. **کلید اشتباه.** `pull` با توکن دستگاه دیگر `unauthorized` می‌گیرد.
۳. **کلید تکراری.** `join` دوباره با همان کلید `taken` می‌دهد.
۴. **قطع و وصل.** با اینترنت قطع، `push` شکست می‌خورد ولی `dirty` می‌ماند؛
   با برگشتن اینترنت، تلاش دوباره انجام می‌شود.
۵. **بدون حساب.** کل برنامه با `SYNC_OFF` مثل امروز کار می‌کند.
۶. **عبارت‌های کلید.** `7kq4m-2xpt9…`، بدون خط تیره، با `O`/`I`/`L` به‌جای
   `0`/`1` — همه باید یک کلید بشمارند.

## انتشار

۱. حساب Cloudflare ساخته می‌شود و `wrangler login` در مرورگر انجام می‌شود.
۲. `wrangler d1 create hesab` → شناسهٔ دیتابیس در `wrangler.toml`.
۳. `wrangler d1 execute --remote --file=schema.sql` → دو جدول.
۴. `wrangler deploy` → نشانی `*.workers.dev`.
۵. `SYNC_URL` در `app.js` با همان نشانی پر می‌شود؛ `CACHE` در `sw.js` یکی بالا
   می‌رود.
۶. تست انتها به انتها روی سایت زنده، سپس push به `main`.

مرحلهٔ ۱ به مرورگر خود کاربر نیاز دارد و بدون اجازهٔ او ممکن نیست.

## ریسک‌ها

- **کلید بازیابی همه‌چیز است.** از دست رفتنش یعنی از دست رفتن نسخهٔ ابری.
  فایل پشتیبان JSON تنها راه نجات است.
- **کلید در `localStorage` است.** با دسترسی به دستگاه، داده قابل خواندن است —
  همان سطح امنیتی که امروز دارد.
- **Worker عمومی است**، ولی بدون کلید چیزی برنمی‌گرداند.
- **D1 رایگان است** تا حجم کمی؛ برای یک دفترچهٔ شخصی سال‌ها کافی است.
